# 传感器到 PL 的增量开发与实测闭环

先读取用户工程规则与当前证据，辨认本轮是设计、实现、分析还是交付。保留用户选择的架构、协议与竞赛规模；技能本身不授权接线、烧录、改协议或公开推送。

按任务选择参考，不一次加载所有材料：

- 新题目规划、实现与阶段验收：读 [workflow.md](references/workflow.md)。
- 图纸、采样、数值、CDC、ILA 或工具异常：读 [pitfalls.md](references/pitfalls.md) 中对应条目。
- 与 AI 协作的可填写任务书：读 [prompts.md](references/prompts.md)。
- 需要知道经验从何得出及其验证边界：读 [case_study.md](references/case_study.md)。
- 已有参考/实测整数 CSV：复制 [project_profile.json](references/project_profile.json) 为新题目修改列映射，再运行 scripts/check_csv.py。该工具只对照，不生成黄金参考。

从图纸追踪器件管脚→网络名→连接器→电压域，明确图纸确认与实物测量的区别。没有图纸不猜接线；不能把本案例的 M14/U18 或校准参数搬给其他板。

每项实现先写输入输出、数据格式、复位、错误恢复、队列/有效信号与周期合同，再写最小模块和自检。大规模新 RTL 是否要批准由用户工程规则决定。正常、错误、恢复均要有可观测断言；数值参考、仿真、综合、板测分别取证，历史 PASS 不能替代当前运行。

分析实测先确认原始/校准/滤波模式、启动初态、时间对应和尺度，再比数值。多个仪器的窗口编号可能有固定偏移；用序号、九项特征和采集时间定位，不能仅凭截图相似或递增窗口号宣称同次匹配。缺失数据与重建数据分开标记。

交付时保存工具版本、依赖与许可证、准确命令、所选 bit/ltx/固件身份、文件哈希、当前验证范围和剩余限制。技能经验须写触发、定位、纠正、证据与失效条件；将真实用户/助手正文与提炼的总结分开。比赛的功能演示足够后按用户目标收尾，不自动追加工业级验证或迁移到 PS/PYNQ。
