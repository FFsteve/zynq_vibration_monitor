# 可填写的协作提示词

这些是从实际成功流程和纠错中提炼的模板，不冒充原聊天逐字引用。原始交互在工程 report/ai_records/。

## 设计与分期

“这是一个[时间预算]内由[能力/人数]完成的[FPGA应用]。先读[规则、现有代码、原理图、工具版本]。目标为[最小演示]，架构保持[用户选择]，协议保持[布局]。先解释输入输出、状态/寄存器、数值格式、周期与错误恢复，列阶段产物和每阶段可独立运行的验收。未知引脚/供电明确未验证，本轮[仅设计/已授权小范围实现]。”

## 实现一个模块

“按已确认的[合同路径]实现[模块]，保持[既有接口]。配套自检覆盖正常、错误、恢复以及[本模块关键边界]。使用独立参考，不以新实现生成自己的黄金答案。实际运行[可用工具]，保留失败与纠正，报告准确命令、检查数、警告和未运行项。没有工具就如实说明，不写通过。”

## 实测分析

“数据在[目录]，D0=[含义]、D1=[含义]、其他通道=[含义]。使用[原始/校准/滤波]固件，[启动/复位/采集顺序]，操作为[静止/移动时间]。先核文件身份、SEQ/校验/时间与边界，再做数值比较。未知初态、探头缺口和重建样本分别标识；ILA 必须确认同次数据对应后才逐窗匹配。”

## 失败排查

“现象是[原始错误/波形]。从[工具启动、编译、TB、约束、IO、协议、数值、状态]逐层排除，优先最小可验证假设。引用证据路径，给出能证伪假设的检查。不要先整体重写、屏蔽时序或改阈值来得到通过。”

## 比赛收尾

“按[正式条款]交付[当前版本]，设计报告[本次/后续]。核心功能已[实际证据]，不追加工业级测试。准备自有开源许可、依赖边界、工具版本、源代码/自检/构建、配对下载成果、资源/时序、实测与参考、真实 AI 正文和可迁移 Skill。README 映射目录结构，技能 README 单独列用法/适用/失效/效果来源。独立目录实际校验后按[明确授权]提交/推送，不把打包成功当全部板测通过。”
