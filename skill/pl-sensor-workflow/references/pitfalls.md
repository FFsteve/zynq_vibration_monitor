# 踩坑与定位清单

各项来源于本案例真实出现的失败或观测；常数是案例值，迁移时必须替换。完整原始用户/助手正文位于工程 report/ai_records/，归纳位于 report/ai_devlog.md。

| 触发条件 | 定位步骤 | 已采用的纠正/结论 | 验证效果与边界 |
|---|---|---|---|
| 时钟约束看似来自相近开发板 | 沿振荡器输出→网络→封装追踪，不只看网名相似 | 早期 U13 改为 U18；U13 实为下拉的其他 IO | 图纸追踪及后续 Vivado 引脚检查，不能替代实际电压测量 |
| PA9 连 K14 后又接 COM2 跳帽 | 查完整 RS232 收发器和跳帽路径，识别是否两个输出争用 | 直连 TTL 时隔离另一驱动；不能把 DB9 电平接 FPGA | 图纸解释、后续通信闭环通过；其他板重新核图 |
| I2C 接口或 USB 串口用错 | 查板卡具体修订与连接器编号，区分 PA9 输入监听和 FPGA M15 回传 | 采用 PB10/PB11 I2C2；保留 OLED 所占另一接口；外置 TTL 接收 M15 | 实际 I2C/UART 同次数据匹配；不猜不同修订板连接 |
| PowerShell 禁止执行 | 看报错是否在仿真器启动前 | 仅本次进程 ExecutionPolicy Bypass，不改系统全局策略 | 实际运行脚本；启动失败不是 RTL 失败 |
| ModelSim DLL 重定位/XSim 子编译失败 | 分开工具进程、编译和 TB；保存完整失败日志 | 在已授权的正常环境重试，修正工具参数；不改系统安全设置 | 后续真执行通过，第一次失败保留 |
| 测试平台失败而设计可能正确 | 核对断言含义和整数常量位宽 | 单 A5 不算完整坏校验候选；5e9 超时改显式 64 位 | 纠正 TB 期望后重新跑，不放宽错误与恢复条件 |
| 把“设计阶段完成”当 RTL 完成 | 检查实际文件与运行记录 | 数值设计单独标 RTL_NOT_RUN，批准后才实现新模块 | 阶段4从数值通过到双工具通过分开记录 |
| CDC 对象在展开阶段不存在 | 核对 top 层次及 XDC 的综合/实现用途 | 仅综合后读实现 CDC，只切 RX 输入到第一级 D；二级路径继续计时 | 两个顶层隔离检查无缺失对象；不对所有路径 false_path |
| OOC 保持失败或父接口未约束 | 分内部寄存器路径与抽象端口预算 | 报告只签核实际约束范围，整板另验证 | OOC 结果未冒充 IO 签核 |
| raw 模式资源突然变少 | opt_design 后查网表是否计算分支被裁剪 | 使用真实保留的调试快照并检查三轴支路/唯一 TX | 分支检查通过；网络 MARK_DEBUG/KEEP 本身不保证全部保留 |
| FIR 结果只有负数差一 | 检查有符号扩展、右移与半单位舍入 | 明确定点半单位远离零、累加上界与饱和；PC 与 RTL 同合同独立比较 | 极值、半单位及实际 RTL 对照通过 |
| 特征比预计晚一拍 | 从原始解析帧的沿开始列周期 | 217 拍改为 218 拍，漏计进入滤波器的一拍 | 集成 TB 确认；不能只改文档数字掩盖错误 |
| MEM 本地与清单哈希不符 | 对真实磁盘字节计算，检查 CRLF/LF 与编码 | 系数固定 LF，Git 禁止其他文件自动换行 | 构建/包内哈希核验；改系数需新版本与重新验证 |
| 静止 Z 正反不对称 | 先 WHO_AM_I/配置和 I2C 原始六字节→UART 对照，再长六面 | 短 50ms 校准降为试验；r1 拟合、独立 r2/r2b 验证后更新 | 不用验证集重新拟合使结果看似更好；不是通用模块参数 |
| 一组姿态受触碰/方向不稳污染 | 查全段方差、横轴残差、操作记录，补独立一面 | 替换问题记录并保留复测来源说明 | 静态重复验证通过，不改原始值“修平” |
| 校准固件与原 SensorSource 混淆 | 检查宏、目标名、头文件参数 ID 与 HEX 指纹 | 独立 SensorCalibratedTrial 仅加校准，其余采集/错误恢复共用 | 全输入 C/Python 与真实 I2C→D0 精确匹配；不能再拿 D0 当原始拟合 |
| 约 250Hz 却周期性有 3ms 间隔 | 同次 I2C、D0、D1 逐层比较、确认记录精度 | 如实报告约 250.5Hz 与短间隔，未确定根因 | 不能把时间标签改成严格 4ms 或称硬件时钟故障已定位 |
| UART 一路缺帧 | 看另外一路与 I2C 是否连续，检查探头触碰时间 | filter_test_2 的 62 帧、test_4 的 5 帧 D0 缺口单列；重建标明来源 | 已重建不等于原始测得；未知初态不能宣称全段精确 |
| 启动前没采或只复位 STM32 | 找首包、静默是否超过断流门限，区分全局配置与流重启 | test_3 依据 >12ms 静默建立初态；末尾半包单列采集边界 | 4914 完整滤波回包全匹配，不冒称 FPGA 全局冷启动 |
| bit 下载成功但无 debug hub | 检查 bit 是否带 ILA、ltx 是否同次生成，再看自由时钟和扫描链 | 错误的 filtered bit + debug ltx 改为同目录 debug 配对 | 实际检测到 1 个 ILA；加载 ltx 不会给普通 bit 增加 ILA |
| 以为 1024 点能显示整个窗口 | 计算深度/PL 时钟，区分窗统计和快照 | 50MHz 下只覆盖 20.48μs，以 feature_valid 触发已锁存特征 | 一拍事件与保持数值通过；不能把时钟采样深度当传感器样本深度 |
| ILA 显示全零或旧窗口值 | 检查是否已 run、是否有效、触发前字段是否陈旧 | 只对 quality/alarm_valid 生效的已发布字段下结论 | 未触发或无效字段不是自动的算法零输出 |
| ILA 窗口号与 DL16 局部编号不符 | 核对是否重下载、同次触发；用 SEQ 和所有特征唯一匹配 | static ID5620 对局部0，motion ID53/54 对局部6/7 | 三窗全部 MS/RMS/峰值精确一致；不能仅凭偏移猜配对 |
| 以为报警图是 Z 轴 | 核对掩码位序及十六进制数 | 最终演练 001 是 X；RMS 3372/827/1282 | 三张图支持静止/置位/正常恢复，恢复图不等于捕获解除边沿 |
| 为演示追加大量工业测试 | 重新对照用户规模与竞赛条款 | 收缩为核心数字证据与一次三状态演练，长时间与三轮冷启动可选 | 用户明确竞赛原型后纠正要求过重，不继续制造阻塞 |
