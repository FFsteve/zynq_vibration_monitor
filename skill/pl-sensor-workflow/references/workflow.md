# 可迁移的阶段工作流

## 先建立最小合同

为新项目填写：目标与时间预算、器件/板卡/工具版本、传感器与电压、输入协议、采样率及其来源、数据格式/数值范围、输出展示方式、预期错误恢复、已完成证据、必须完成和可选项。未知必须单列，不能用旧题目的常数补全。

| 阶段 | 输入与设计问题 | 可独立验证的产物 | 继续条件 |
|---|---|---|---|
| 图纸和边界 | 真实 PDF、板卡修订、网络与电压路径；采用什么处理架构 | 引脚追踪表、候选约束、风险/未知清单 | 消除明确图纸错误；未测供电仍标未知 |
| 字节接收 | 时钟/波特率、异步同步、起止位、采样中心、计数器范围、BREAK/复位后空闲 | 一个接收模块与 TB | 全字节、连续帧、相位/误差、坏起止、复位恢复通过 |
| 成帧与发送 | 包长度/字节序/校验范围、截断、超时边界、原子更新、序号回绕、TX 忙时如何排队 | 解析器、TX、独立链路 TB | 坏帧不污染输出，截断后恢复，队满行为可计数 |
| 原始实物闭环 | 先固定源，后传感器；WHO_AM_I/配置回读、DATA_RDY、六字节一致性 | MCU 标准库应用、PC 解析、D0/D1/I2C 对照 | 位宽/内容/校验/序号分别检查；通信通过不等于量值通过 |
| 数字处理 | 频段/采样率、位宽、舍入、饱和、累加上界、历史清空、每样本周期预算 | 独立整数与浮点参考、系数与哈希、FIR/去直流 RTL/TB | 极值/半单位/脉冲/阶跃/频点/随机通过；实际 RTL 输出与参考一致 |
| 特征与报警 | 窗长、统计公式、整数开方、质量有效、滞回/连续确认、复位与缺样 | 特征/报警模块与 TB | 更新事件单拍、数据保持、边界错误不发布半窗 |
| 集成与量化 | 输出缩放/协议兼容、队列拥塞、计算支路是否真实保留、唯一外部发送器 | 顶层、批处理构建、实际 RTL 样本导出、资源/时序 | 检查真实网表与约束，不能拿 OOC 内部通过替代整板实现 |
| 校准与多源实测 | 先核配置，六面足够长并独立复测；分离原始/校准源与 FPGA 滤波 | 参数来源、整数公式、C/Python 对照、独立重复集验证 | 训练与验证分开；不把去直流当校准，不对运动污染记录硬拟合 |
| ILA 与演示 | 配对下载文件、自由运行时钟、有效位、采集顺序、数据对应 | CSV/截图/事件、参考计算、静止→报警→恢复 | 数值证据与声音现象分别记录；竞赛目标达到即转收尾 |
| 外设小扩展 | 只旁路观察现有质量/报警，不改变处理反馈；驱动极性/有源无源 | 独立模块/顶层、对照 TB、新构建 | 新旧输出对照通过，新增引脚正确且实物响应确认 |
| 版本与交付 | 同一套源码/系数/固件/bit/ltx，工具与依赖许可、选定数据 | README、运行入口、文件清单、MIT 自有许可、Skill | 独立目录验证；历史与当前状态分开；用户授权后再公开推送 |

该表不是所有项目必须逐项购买设备或做满压力测试的标准。时间紧时优先保留核心正确性、自检、真实演示、资源时序及复现文档；其他工程测试按用户场景列为扩展。

## 数值与时序的四份合同

1. 数学合同：公式、状态初值、有效样本定义、溢出/饱和、正负数舍入方式；软件参考不能只逐行翻译 RTL。
2. 流合同：输入/输出事件、并行与串行吞吐、计算忙时行为、何时丢弃/重启、SEQ 与复位优先级。
3. 周期合同：逐拍画入队、接纳、更新、发布，计数从哪个沿开始；区分算法群延迟、运算延迟、窗时长与 UART 发送时间。
4. 证据合同：数值设计、RTL 仿真、OOC、整板实现、板测分别标识。先作废旧结果，只有进程真实结束、自检哨兵/错误数与新文件都匹配才通过。

## 可复现交付最小集合

自有源码与自检、系数和数值合同、构建脚本、工具版本/器件、第三方依赖准备、资源/时序报告、实际输出与独立参考、下载文件配对身份、接线/操作和明确限制。目录结构可自定，在工程 README 映射即可；技能 README 单独说明技能的适用范围/用法/失效条件与效果来源。
