## 实现内容与作用

| 文件 | 职责 |
|---|---|
| `rtl/dc_remove.v` | 每轴Q16基线估计，仅随有效样本更新，17位相减避免溢出，正负半单位远离零舍入 |
| `rtl/fir_lp_serial.v` | 63抽头环形历史、每轴一套串行乘加、41位累加、18位输出及饱和保护 |
| `rtl/vibration_filter.v` | 三轴快照/SEQ对齐，忙时丢弃计数，跳号/重复/断流重建历史 |
| `rtl/filter_monitor_core.v` | 复用既有通信核心，原始回传旁增加内部滤波结果接口 |
| `sim/tb/tb_*.v`中的四个新增测试 | 自检正常、错误、复位和恢复，逐样本对照独立期望 |
| `.gitattributes` | 固定系数存储文件的LF，避免Windows检出换行破坏SHA256 |
| `sim/tb/stage4_check.vh`、`stage4_negative_cases.v` | 统一完成/评分标记；缺失系数与非法阈值拒绝测试 |
| `host/stage4_vectors.py` | 从数值参考生成单轴、三轴和串口集成期望向量 |
| `host/check_stage4_captures.py` | 对实际RTL导出重新比对，并测量实际输出正弦增益 |
| `sim/run_stage4.ps1`及ModelSim/XSim脚本 | 双工具编译运行，系数哈希、结果、导出及负向检查 |
| `sim/check_stage4_negative.ps1`及专用脚本 | 预期拒绝必须有明确错误标记且不能走到意外接纳哨兵 |
| `scripts/check_stage4_synthesis.ps1/.tcl` | 独立OOC计算模块资源和内部时序，不操作板级工程 |

RTL、TB和脚本说明性注释使用中文；新PS1为UTF-8 BOM。没有修改原有UART RX/TX/解析器、通信核心、板级top、STM32、XDC或烧录设置。18位滤波结果保留为内部接口，没有静默截成16位原始字段，也没有改十字节协议。

当前下载在板上的旧top不会因新增源码自动出现滤波效果；D1仍应回传原始包。后续特征模块可连接新增内部接口。

## 实际命令

从项目根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\sim\run_stage4.ps1 -Simulator both
```

该最终一键流程退出码0，包含四项自检、两套RTL导出检查以及每工具两项负向用例。日志在 `build/stage4_final_run.log`。随后补足集成测试的1～9字节各截断位置，针对该修改单独重跑：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\sim\run_stage4.ps1 -Simulator both -Test filter_monitor_core
```

最终针对性回归同时补足载荷含A55A/5AA5及有符号极值的检查，退出码0，日志在 `build/stage4_adapter_final.log`，下表采用最新结果。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check_stage4_synthesis.ps1
```

最终OOC流程退出码0，结果为 `PASS stage4_ooc setup_slack=9.198 hold_slack=0.117`。所有输出位于隔离的 `build/`，没有生成比特流或连接Hardware Manager。

## 遇到的问题与纠正

1. 初次在受限执行环境启动ModelSim时报系统DLL重定位错误，XSim子编译器也未完成。改在获准的常规进程环境运行已安装工具，版本及仿真正常；没有修改Windows安全设置、工具安装或许可。
2. 首次XSim命令错误地沿用ModelSim的 `+incdir+` 语法，改为xvlog的 `-i`；修正后重新编译与运行，没有将编译失败计为PASS。
3. 实现阶段明确了断流计数的阈值边界：用可保存LIMIT的饱和计数，区分“本沿达到阈值”与“已经过期”，避免历史标志提前一拍失效，TB验证前/等于/后一拍。
4. 首次OOC给抽象端口设置0ns输入/输出延迟，出现输入端到首级寄存器保持违例，最差-0.502ns。该接口没有父级路径依据，与原定内部时序验收范围不同。已移除虚构端口预算，保留20ns计算时钟，严格检查内部寄存器建立/保持，明确把接口和父级时钟签核留给集成；没有修改RTL或用false_path掩盖内部路径。首次报告保存在 `build/stage4_synthesis/initial_zero_io_*`，不把首次失败改写成通过。

XSim还会提示测试台刻意未连接的诊断输出，负向参数顶层也有未连接输出提示；它们不表示实际模块输入悬空。最终结论依据退出码、自检计数、导出结果和具体时序范围，不能称为所有工具零警告。
