## yp_r2不是独立Y朝上记录

yp_r2与xn_r2的D0、D1、I2C三个CSV分别逐字节相同：

| 类型 | 两目录共同SHA256 |
| --- | --- |
| D0 UART | f8f3ecd12a94f8daaf3f0aa986d39135efcd6a0ec15d9b13e05983bd049b3e0e |
| D1 UART | a8031c4638d1330693c2ee139e05d49a7f08aecf2f028384b567db00c6705f61 |
| I2C | 6749b6979fa24c5f3549c8911bd7fb10ea4a51ca13fc22d83531fb334a6a0882 |

两份atkdl外部文件哈希不同，但逐通道按排序条目计算内部采样bin内容指纹后，D0～D3四路全部相同。每路48个bin条目、50331648字节；核查不是只比较文件名、均值或外层ZIP。两个目录都包含均值约−15568/−702/+6218的记录，其主轴是负X，不能当作正Y。

因此不能把假yp与yn计算出的巨大Y零偏/灵敏度差当成器件失效。最终JSON把Y重复性诊断值设为null。需要查找真正的Y朝上原始记录；如果没有另存，需重新采集Y朝上。仅从当前yp_r2原波形重新导出CSV不能找回缺失的Y朝上，因为原波形本身也是重复采样。
