**2. STM32 → FPGA 链路与 10 字节数据包**

第一阶段链路建议保持为：

```text
MPU6050 → STM32 I2C采集 → USART1 TX
        → J3.1 / K14 → UART RX → 包解析 → 三轴数据寄存器
        → UART TX → M15 / J3.2 → 外置USB串口RXD → PC
```

STM32 和 USB 串口均与 FPGA 共地。此架构仅使用 PL。

传感器原理图：:codex-file-citation{path="D:/Code/zynq_vibration_monitor/zynq_vibration_codex_handoff/docs/hardware/mpu6050_module_schematic.pdf" purpose="source"}，PDF 第 1 页确认模块使用 3.3 V，SCL/SDA 各有 2.2 kΩ上拉，AD0 有 4.7 kΩ下拉，默认 7 位地址为 `0x68`。

模块手册：:codex-file-citation{path="D:/Code/zynq_vibration_monitor/zynq_vibration_codex_handoff/docs/hardware/mpu6050_module_manual.pdf" purpose="source"}，第 5 页接口定义与上述原理图一致；第 6～11 页介绍采样配置、寄存器读取和初始化。

交接文档约定 STM32 使用 PA9、PB6、PB7，但这四份 PDF **不能验证 STM32 最小板的板级连接**。后续 STM32 程序仍使用标准库。

当前包格式长度正确：

| 字节偏移 | 内容 | 解释 |
|---|---|---|
| 0、1 | `A5 5A` | 固定包头 |
| 2 | `SEQ` | 8 位序号 |
| 3、4 | `XH XL` | X 轴，16 位补码，高字节先发 |
| 5、6 | `YH YL` | Y 轴，同上 |
| 7、8 | `ZH ZL` | Z 轴，同上 |
| 9 | `CHK` | 偏移 2～8 的 7 个字节逐字节异或 |

需要区分两种顺序：**轴数据高字节先发，但 UART 每个字节内部仍然低位先发。**

可用于后续验证的样例：

```text
A5 5A 01 00 01 FF FF 80 00 81
```

其含义为 `SEQ=1，X=1，Y=-1，Z=-32768`，校验值为 `81`。

115200、8N1 下，每字节占 10 个串行位：

- 一包占 100 位，耗时约 **868.06 μs**。
- 250 包/s 需要 25,000 bit/s，占链路约 **21.70%**。
- 按 4 ms 一包计算，连续发完一包后约余 3.13 ms。

这些是理论计算，不能证明 STM32 已实现稳定的 250 Hz 采样。`delay_ms(4)` 也不能保证与传感器新数据同步。

包格式可以作为首版，但需在 RTL 前补齐以下约定；以下均为建议，尚未冻结：

- `SEQ` 按模 256 递增；跳号、重复用于诊断，不直接判为校验失败。
- 完整校验成功时，三轴及序号同时更新，`frame_valid` 拉高一个 PL 时钟周期。
- 包解析器采用最近 **10 个字节的滑动窗口**检查包头及校验，避免截断包吞掉紧随其后的完整包；载荷中出现 `A5 5A` 也不立即重启解析。
- 建议合法字节之间超过 **2 ms** 未收到新字节便清空窗口；50 MHz 下为 100,000 周期。STM32 必须在此间隔内连续发送包内字节。
- UART 停止位错误时清空解析窗口，随后重新搜索。

XOR 可以漏检抵消的多位错误及字节交换；无转义包头也可能误匹配。因此该协议只能提供有限检错，不能保证任意损坏流下绝不误收。首版可保持现有格式，本轮不擅自换 CRC。

**3. UART RX 的接口、寄存器与采样时序**

建议独立模块名为 `uart_rx`，只负责接收字节。

| 接口/参数 | 方向或默认值 | 职责 |
|---|---|---|
| `CLK_HZ` | 50,000,000 | 输入时钟频率 |
| `BAUD` | 115,200 | 波特率 |
| `clk` | 输入 | 全部逻辑使用其上升沿 |
| `rst` | 输入 | 高有效同步复位 |
| `rx_i` | 输入 | 异步串行信号 |
| `data_o[7:0]` | 输出 | 最近一次合法接收的字节 |
| `valid_o` | 输出 | 合法字节完成脉冲，持续 1 周期 |
| `framing_error_o` | 输出 | 停止位错误脉冲，持续 1 周期 |
| `busy_o` | 输出 | 正在确认起始位或接收数据、停止位 |

`data_o` 在坏帧时保持上次合法值；`valid_o` 与 `framing_error_o` 不同时有效。首版不设置反压接口，下游必须接收每个有效字节。

内部寄存器建议如下：

| 寄存器 | 位宽 | 用途 |
|---|---:|---|
| `rx_meta`、`rx_sync` | 各 1 | 两级同步，逻辑只使用第二级 |
| `rx_prev` | 1 | 检测同步信号下降沿 |
| `state` | 3 | 五状态 FSM |
| `baud_cnt` | 默认 9 | 半位、整位及恢复等待计时 |
| `bit_idx` | 3 | 数据位索引 0～7 |
| `shift_reg` | 8 | 暂存当前字节 |
| 输出寄存器 | 对应接口 | 保存数据及生成单周期脉冲 |

默认计时参数：

```text
CLKS_PER_BIT = round(50,000,000 / 115,200) = 434
HALF_BIT     = 217
```

等效波特率约为 `115207.37`，分频误差约 **+0.0064%**。采用一个 50 MHz 时钟和计数使能，不生成新的低速逻辑时钟。

| 状态 | 行为与转换 |
|---|---|
| `WAIT_HIGH` | 复位后或坏停止位后进入；要求同步 RX 连续高电平一整位，再进入 `IDLE` |
| `IDLE` | 等待同步 RX 下降沿；检测后开始半位计时，进入 `START` |
| `START` | 半位后检查 RX；低则确认起始位，进入 `DATA`；高则按假起始位丢弃并返回 `IDLE` |
| `DATA` | 每隔一整位采样一次，依次写入 `shift_reg[0]`～`[7]`；完成后进入 `STOP` |
| `STOP` | 再等一整位采样；高则提交字节并返回 `IDLE`；低则报错并进入 `WAIT_HIGH` |

以**识别到同步下降沿的时钟沿为 t=0**：

| 采样点 | 相对周期数 |
|---|---:|
| 起始位中心 | 217 |
| D0 | 651 |
| D1～D6 | 每次再加 434 |
| D7 | 3689 |
| 停止位中心 | 4123 |

物理引脚到这个时间基准另有同步及检测延迟，Testbench 不能将两者混为一谈。

计数器必须明确“等待 N 周期”的定义。例如下降沿处装载 `216`，以后每周期递减，到零时采样，对应等待 217 周期；整位装载 `433`。这能避免常见的多算或少算一周期。

合法停止位在中心确认后直接返回 `IDLE`，可接收仅有一个停止位的连续字节。错误恢复则有明确条件：**先提供至少一整位高电平，再发送新字节**。这样长时间拉低不会持续产生重复错误或伪字节。

该版本采用单点中心采样。数据位中心受干扰时可能收到错误字节，8N1 无法自行识别这种错误，需由上层包校验处理。

模块的 `rst` 是逻辑接口，不代表增加一个尚未核实的板级复位引脚。顶层上电复位方式需在实现时明确。

**4. UART RX 的自检 Testbench 方案**

使用独立的 UART 激励任务，按时间发送串行波形；标称位宽使用 `1/115200 s`，避免激励与 DUT 同用 434 周期而掩盖分频问题。评分器自动检查数据、脉冲数量、顺序和错误恢复。

| 类别 | 测试内容 | 判定标准 |
|---|---|---|
| 复位与空闲 | 高、低电平下复位，长时间空闲 | 无有效数据；低电平启动必须先恢复 |
| 数据覆盖 | 全部 256 个字节；重点 `00/FF/55/AA/01/80/A5/5A` | 每字节恰有一次正确输出 |
| 连续字节 | 一个停止位后立即发下一字节，长随机序列 | 无丢失、重复或乱序 |
| 空闲间隔 | 随机字节间隔 | 正确接收，不产生额外事件 |
| 异步相位 | 起始沿相对 20 ns 时钟遍历多个相位 | 合法帧均正确接收 |
| 波特率偏差 | 发送端相对标称值 ±1%、±2%，叠加小幅边沿抖动 | 作为拟定的正常接收验收范围 |
| 假起始位 | 短低脉冲，起始中心附近前后翻转 | 中心为高则拒收，无 `valid` |
| 坏停止位 | 停止位中心拉低，覆盖不同数据模式 | 一次错误脉冲，无有效字节 |
| BREAK | 持续低电平多个字节时间 | 不反复报错；恢复高电平后可接收 |
| 中途复位 | 在 START、各数据位、STOP 中复位 | 丢弃当前字节，后续恢复 |
| 数据位毛刺 | 在采样点之外及中心注入毛刺 | 按采样模型检查；不错误宣称能纠正毛刺 |
| 参数与边界 | 默认参数及另一组合法分频参数 | 位索引、终值和计时无越界 |

另外加入：

- 全局 watchdog，超时自动失败。
- `valid`、错误脉冲宽度及互斥检查。
- 坏帧后数据保持、复位后输出无未知态检查。
- 输出时间检查，捕获半位/整位计数偏差。
- 可复现的随机种子和首个失败现场。

包解析器另配自检 TB，覆盖负数、序号回绕、错误包头、单字节损坏、插入/删除字节、各位置截断、超时边界、载荷含包头，以及坏流后紧接完整合法包。

数字仿真不能验证真实亚稳态和电气电平；这些需后续 CDC 检查、实现检查及板测补充。

**2. 模块边界与实现顺序**

建议系统保持以下层次，便于你理解和定位问题：

```text
STM32：
I2C驱动 → MPU6050驱动 → 采样调度 → 数据打包 → USART1发送

FPGA PL：
UART RX → 包解析 → 三轴样本寄存器
                      ↓
              去直流 → FIR
                      ↓
              窗口均方值 / 峰值 → 阈值报警
                      ↓
                回传控制 → UART TX → PC
```

这里有三个需要提前明确的设计原则：

- **UART 按字节工作，解析器按数据包工作，滤波器按有效样本工作。** 不将串口位计时与滤波采样混在一起。
- 后续处理必须由 `sample_valid` 驱动。目标 250 Hz 不代表每经过固定数量的 PL 时钟就必定有一个新样本。
- 三轴分别保存滤波和特征历史。可以复用运算单元，但不能共用一套历史数据。

一周内建议先实现一版 **16 抽头 FIR**，作为可调整的工作起点。具体截止频率、系数和去直流方法，应根据实际采样率、演示振动频率确定，现阶段不直接给定。

**3. 仿真应分三层，不能只看波形**

| 验证层次 | 检查对象 | 主要目的 |

| 模块自检 | RX、TX、解析器、复位、去直流、FIR、特征、报警 | 确认模块接口、数值与边界行为正确 |
