# 当前项目的 DL16 逻辑分析仪测试指南

更新日期：2026-10-30。实际型号：**DL16 / ATK-PTDL16，非 DL16 Plus、非 DL32**。适用于第三阶段 STM32 标准库固件、I2C2/PB10/PB11 和 FPGA UART2/K14/M15 方案。

本文主体为操作方案与预期波形。用户已提供 FixedSource 回传截图，且 2026-10-30 授权查看 SensorSource 已有采集：12 组 I2C→D0→D1 数据对照通过，但静止量值约 1.34g（以 ±2g 配置生效为前提）需排查，初始化尚缺直接捕获。实际证据与边界分别见 `../report/stm32_fixed_uart_validation.md` 和 `../report/sensor_source_validation_20261030.md`；不要把本文操作预期当作全部实测通过。

## 一、这台仪器如何设置

用户于 2026-10-29 确认实际购买 DL16，并补充 `F:/说明书/逻辑分析仪产品差异说明.xlsx` 和 `F:/说明书/ATK-Logic_CN.pdf`。本版以这两份资料为准；此前 DL32 规格不再作为本机设置依据。

### 与上一版相比，需要修正什么

| 项目 | 本机 DL16 的依据与设置 |
|---|---|
| 输入通道 | 16 路 |
| USB 接口 | USB2.0 Type-C；不是 DL32 的 USB3.0 |
| Buffer 最高采样率 | 16 路 / 250 MS/s；不使用 DL32 的 1 GS/s 设置 |
| Stream 最高采样率 | 3 路 / 100 MS/s、6 路 / 50 MS/s、16 路 / 20 MS/s |
| 硬件缓存 | 1 Gbit，不是 3.5 Gbit，也不是 1 GB |
| 最小可采集脉宽 | 8 ns |
| 最高可采集信号频率 | 50 MHz，与最高采样率 250 MS/s 是两个参数 |
| 运行模式 | Buffer、Stream；**没有 Roll 模式** |
| 触发 | 基本边沿/电平触发；**不使用 DL32 类串行/并行高级触发** |
| 协议解码 | 仍支持 UART/I2C 等解码；解码不等于硬件协议触发 |
| 接口 | 2.54 mm 杜邦接口、标准 20 针牛角座；不是 DL32 的 1.27 mm 屏蔽线接口 |
| 波形输出 | 2 路 PWM；当前测试全部关闭，不是 4 路 |

依据为差异表“产品差异”页的 DL16 列，以及手册 PDF 第 5 页（印刷页码 2）的 DL16 参数表。差异表部分单元格跨型号合并，例如 USB2.0 和 Stream 参数适用于 DL16 与 DL16 Plus，不能把合并区域的空格误判为功能缺失。

门限范围仍为 -5V～+5V、步进 0.1V，当前 3.3V 信号推荐 1.6V；手册的 UART 示例也使用此值。**本项目继续用四路、20 MS/s 即可，无需为了更正型号而改变板卡接线、波特率或 I2C 配置。**

参数表中的最小 8 ns 脉宽是仪器能力指标，不代表当前 20 MS/s（50 ns 采样间隔）能保证捕获 8 ns 毛刺。当前设置用于 UART/I2C 通信检查，不把它解释为高速毛刺验收。

| 项目 | 当前建议 | 用途 |
|---|---|---|
| 启用通道 | 四路，其它先关闭 | UART 输入/回传、I2C SCL/SDA |
| 采样率 | **20 MS/s**，有的软件显示为 20 MHz | 采样间隔 50 ns，足以观察 115200 UART 和 100 kHz I2C |
| 输入门限 | **1.6V** | 针对当前标称 3.3V 数字信号的起始设置，不是测量结果 |
| 捕获方式 | **Buffer + 正常** | 单次触发，采满后上传，不是边采边显示 |
| 常规捕获时长 | **100 ms**；20 ms 也可用于短记录 | 固定源约有 25 个或 5 个包周期；边界可能截断帧 |
| 初始化捕获 | **Buffer + 立即，2 s** | 不等待边沿触发，在记录窗口内复位一次 STM32，包含约 200 ms 初始化；必要时还能观察重试 |
| 较长记录 | Stream，选择明确的记录时长 | 边采边传；仍需确认软件没有丢样，没有 Roll |
| 触发位置 | 正常 Buffer 先设约 10% | 先预采样，再等待触发；立即采集忽略触发条件 |

20 ms × 20 MS/s = 每通道 400000 个采样点。按手册的裸采样深度公式，四路、100 ms、20 MS/s 为 8 Mbit（约 1 MB），四路、500 ms 为 40 Mbit（约 5 MB），四路、2 s 为 160 Mbit（约 20 MB），低于 DL16 的 1 Gbit 缓存。无需用满缓存或启用压缩来完成这些短测试；软件可能有存储组织开销，最终仍核对界面可用设置及实际记录区间。

### ATK-Logic 软件中的具体操作

以下按用户提供的 V1.5 手册截图说明；2026-10-30 实际打开的软件标题为 ATK-Logic V1.1.2.1。不自动下载软件、驱动或更新固件。

1. 连接 DL16 并打开 ATK-Logic，确认出现对应设备页及连接成功提示。手册中的指示灯为：红色未连接、绿色已连接、蓝色采集中。
2. 右侧打开 **设备配置 → 通道选择**，只保留 0～3。单测 STM32 UART 时只开 0；注意 Clear 仍保留 0 通道，不是全部关闭。
3. **设备配置 → 采集选项 → 运行模式** 选 Buffer；同区的 **采集方式** 选正常。手册正文一处重复写“运行模式”，截图明确区分这两个字段，按截图字段操作。
4. **设备配置 → 采集参数**：采样频率选 20 MHz（20 MS/s）；“时间频率”或采样时间选 100 ms；触发阈值设 1.6V；Buffer 的触发位置先选约 10%。若下拉框没有所述时间，选择能覆盖目标区间的可用值并记录。
5. 左侧 **通道选项** 中，给 CH0 选择下降沿，其它通道不设置触发。多通道触发条件按手册是逻辑与，不能无意中要求几条线同时出现边沿，否则可能一直等待。
6. 点击右侧 **开始采集**。正常 Buffer 模式会先准备和预采样，再等待触发；触发并采满后上传。不要因尚未出现波形就判断仪器故障。
7. 捕获后在右侧 **协议解码 → 协议 → 添加（+）** 中添加 UART 和 I2C，设置如下各节。手册也支持采集前配置解码器。

若只想确认线上有没有活动，用 **采集方式：立即**。它会忽略触发条件，采样时长仍照常设置。**循环**会按间隔重复执行整次采集，不是连续无缝记录，也不是 Roll；长记录使用 Stream。Stream 的预触发深度按手册不可改，不要求把它设成 Buffer 的 10%。

先选不带星号 `*` 的普通时间；带星号表示 Buffer 的 RLE 压缩，实际记录时长可能因变化量达不到标称。首次测量先关闭软件毛刺过滤，保留原始异常，排查接线、门限后再考虑滤波。

上述菜单见 PDF 第 19～30、34 页（印刷页码 16～27、31）。本文的 CH0～CH3 对应仪器标注 0～3 的数字输入；20 针接口上的 **G 为地，PWM0/PWM1 为输出**，不按线缆颜色或接口朝向猜测。接口说明见 PDF 第 6 页（印刷页码 3）。

## 二、探头怎么接

先完成两板原有数据线和共地，再让分析仪探头**并接**到这些信号；不是用分析仪替代原来的连接线。完整板间接线见 [接线指南](wiring_guide.md)。

| 分析仪输入 | 待测信号 | 建议探测点 | 解码器 |
|---|---|---|---|
| CH0 | STM32→FPGA 数据线 | FPGA 底板 **J3.1 / UART2_RX**，该线来自 STM32 PA9 | UART，115200、8N1 |
| CH1 | FPGA→PC 回传线 | FPGA 底板 **J3.2 / UART2_TX** | 独立的另一个 UART，115200、8N1 |
| CH2 | MPU6050 SCL | STM32 扩展板通讯接口 2 **J3/J4.3 / PB10** | I2C 的 SCL |
| CH3 | MPU6050 SDA | STM32 扩展板通讯接口 2 **J3/J4.4 / PB11** | I2C 的 SDA |
| GND | 公共地 | FPGA 底板 J3.37/39 或已经共地的 STM32 GND | 地参考 |

只测 STM32 串口时，CH0 也可直接夹 STM32 扩展板通讯接口 3 的 J9/J10.3（PA9），GND 接同接口 .5。要确认信号确实送到 FPGA 排针，更有价值的是在 FPGA J3.1 捕获；必要时用两个通道同时测线的两端。

同名 J3 分别属于 FPGA 底板和 STM32 扩展板，不能混淆。接线点是排针，不是 FPGA K14/M15 的 BGA 焊球。使用尽量短的信号线和附近地线，避免抓错针或夹具搭到相邻电源脚。

DL16 通过自身 USB 供电；只接 0～15 数字输入及 G 地参考，不把仪器电源脚接入板卡。它有 **PWM0/PWM1 两路 3.3V 输出**，本次在“设备配置 → 波形输出”中保持关闭，且不接到已有驱动的信号线上。仪器的 ±40V 输入耐压不表示 FPGA 或 MPU6050 能承受该电压。

FPGA P1 的 UART2 与 RS232/RS485 路径按接线指南隔离，避免额外收发器驱动输入。仪器 GND、STM32 GND、FPGA GND 必须共地。断电接探头、复查针号后，再按获准的板测流程供电运行。

## 三、第一步：只检查 STM32 固定数据

使用 Keil 的 **FixedSource** 目标。这个模式不要求 MPU6050 正常工作，先用它验证波特率、字节、打包和发送周期。

### 采集与 UART 解码

1. 启用 CH0，设置 Buffer、正常、20 MS/s、100 ms 捕获，门限 1.6V。
2. 触发选择 CH0 **下降沿**，其余通道不设条件。空闲 UART 为高，起始位为低；触发到数据位的下降沿也可能发生，捕获内后续完整字节仍可检查。**DL16 不使用“收到 A5 才触发”的串行高级触发**；采完后再按 UART 解码结果定位 A5 5A。
3. 在 UART 协议设置中，按手册单线发送示例选择 **TX/UART transmit line=0，RX 留空**，Baud rate=115200、Data bits=8、Parity=none、Stop bits=1、Bit order=lsb-first、Data format=hex，反相项设 no。此 TX 指被观察信号的发送方向，不是让分析仪驱动它。
4. 启动采集后，让 STM32 正常运行；中途抓到的序号不必从 0 开始。要捕获 SEQ=0，改用 **Buffer + 立即、2 s**，确认采样开始后尽早复位 STM32，并确保窗口剩余时间足以记录启动后的数据。正常模式有预采样，且已经运行的 UART 会自动触发，所以不能指望“点击开始后随即复位”总能捕获首包。
5. 放大完整字节，再缩小到十字节包和多个包的时间范围。

### 应看到什么

| 检查项 | 当前软件的预期 |
|---|---|
| 空闲 | 高电平 |
| 单位时间 | 标称 1/115200 ≈ **8.68 us** |
| 单字节 | 起始位+8 数据位+停止位，共约 **86.8 us** |
| 十字节包 | 连续发送约 **0.87 ms** |
| 固定样本 | X=1，Y=-1，Z=-32768 |
| 包起点间隔 | 正常调度目标约 **4 ms**，即约 250 包/s |
| 序号 | 模 256 递增，255 后为 0 |

UART 的“位宽”是单位时间，不是任意一段高/低平台的宽度。连续几个相同数据位会合并成 2 倍、3 倍等位时间的平台，不应把它当成波特率错误。

固定源前两包预期为：

```text
A5 5A 00 00 01 FF FF 80 00 81
A5 5A 01 00 01 FF FF 80 00 80
```

格式是 `A5 5A SEQ XH XL YH YL ZH ZL CHK`，XOR 范围为 SEQ 至 ZL。固定样本下 CHK=SEQ XOR 81。分析仪的 UART 解码只还原字节，不自动理解本项目的十字节布局或 XOR；需要人工分组或导出字节后用项目 PC 工具核对。

## 四、第二步：对照 FPGA 输入和回传

这一步要求 FPGA 已经运行当前 `top`，不能仅靠给空白或旧设计的 FPGA 上电。

1. 同时打开 CH0 和 CH1，使用同一次采集、同一时间轴。
2. 给两路各添加一个 UART 解码器：第一套 TX=0、RX 留空，第二套 TX=1、RX 留空；设置均为 115200、8N1、低位先发、空闲高、不反相。在“协议解码 → 数据 → 更多”中选择要查看的协议列表，避免只看到了其中一路。
3. 用 CH0 下降沿触发，捕获 20～100 ms。
4. 逐包检查 CH0 的输入与 CH1 的对应回传，确认序号、三轴和校验相符。

当前默认 `ACK_ONLY=0`，所以 CH1 应回传**相同内容的完整十字节包**。它是校验通过后重新组包，不是无条件回显每一个输入字节。只有后续使用 ACK_ONLY=1 重新生成并下载的设计，才应看到每包一个 06；不能把接收软件切成 ACK 模式就改变 FPGA 行为。

输入接收器在最后字节停止位中心确认成功，之后启动回传。因此 CH1 的回包起点可能略早于 UART 解码软件画出的“最后停止位完整结束”边界；两路是独立收发线，不能仅凭这点时间重叠判错。应按输入包完成采样、合法性及输出内容判断。

稳定正常输入下，回包不应长时间缺失、顺序错乱或字段变化。故意坏校验包不应得到合法响应，随后合法包应恢复；当前 FixedSource 不会主动造坏包，测试错误恢复需要另外准备可控发送源，不能仅把探头夹上就声称覆盖了该用例。

如果 CH1 波形解码正确而 PC 没收到，优先检查外置串口 RXD、共地、COM 口和 PC 参数。领航者板载 USB 桥走 UART3，当前 M15/UART2 回传不会自动进入那个 COM 口。

## 五、第三步：检查 MPU6050 的 I2C

使用 Keil **SensorSource**。在“协议解码 → 协议 → 添加”中选择 I2C，设 CH2=SCL、CH3=SDA，地址优先显示为七位地址。总线名义 100 kHz；DL16 先用 **CH3/SDA 下降沿**触发、其它通道不设条件，再在波形中找 SCL 为高时发生的 START。数据位也可能产生 SDA 下降沿，因此边沿触发不保证就是 I2C START，不要求本机提供 I2C 协议触发。

### 启动身份检查

为可靠包含初始化，先设置 **Buffer、立即、20 MS/s、2 s**，确认采样已开始后尽早复位 STM32，确保窗口内覆盖复位后至少 500 ms。立即模式不等待触发，避免正在轮询的 SDA 提前触发或预采样尚未完成时漏掉第一笔事务。捕获后再定位复位后的 WHO_AM_I(75)，预期事务为：

```text
START
68 W   ACK       原始地址字节 D0
75     ACK       寄存器地址
重复 START
68 R   ACK       原始地址字节 D1
68     NACK      WHO_AM_I 数据，由主机结束单字节读取
STOP
```

七位显示 68、原始总线地址字节显示 D0/D1 都可能正确：D0=(68<<1)|0，D1=(68<<1)|1。不要把解码器的七位/八位显示差异误认为地址错误。地址阶段应收到从机 ACK；主机在最后读完一个字节后发 NACK 是正常结束。

身份正确后，当前程序依次写复位与配置：

```text
6B=80，等待约 100 ms
6B=01，等待约 100 ms
1A=02
19=03
1C=00
38=01
随后回读上述配置
```

这两段等待来自当前源码，所以开始约 200 ms 的初始化阶段不能期待均匀的 4 ms UART 采样包。若身份/配置失败，应用约一秒后重试；捕获太短可能只看到空闲。

### 稳态采集

当前代码轮询 INT_STATUS(3A)，发现 DATA_RDY 位为 1 后，从 ACCEL_XOUT_H(3B) 连续读 **6 个字节**：

```text
START → 68 W ACK → 3B ACK → 重复 START → 68 R ACK
→ XH ACK → XL ACK → YH ACK → YL ACK → ZH ACK → ZL NACK → STOP
```

应检查：

- 空闲时 SCL/SDA 都为高；名义 SCL 周期约 10 us，软件开销或时钟拉伸可延长低电平，不要求占空比正好 50%。
- 地址阶段和非末尾数据字节的 ACK 正常，最后一个读字节由主机 NACK 后 STOP。
- 实际读到的六字节与随后 UART 包中第 4～9 字节一致，保持 XH/XL/YH/YL/ZH/ZL 顺序。
- 3A 状态轮询可能比 250 Hz 更频繁，不能要求每 4 ms 只出现一次 I2C 事务。
- 相邻有效样本/发送起点目标约 4 ms，仍需测量抖动和是否迟到。没有 FIFO，发送序号连续也不能证明未漏读传感器内部的样本。

只轮询 INT_STATUS、没有六字节读取，先检查 DATA_RDY 返回值和配置回读；地址阶段 NACK 则先查供电、地址、SCL/SDA 和共地。

## 六、常见现象如何定位

| 波形/解码现象 | 下一步 |
|---|---|
| CH0 始终为高 | 检查 STM32 固件是否运行、探测点；SensorSource 还需确认是否卡在身份/初始化重试；可换 FixedSource 隔离传感器因素 |
| CH0 长时间为低 | 先查错针、短路、接地和 P1 额外驱动；不要立即认定 RTL 错误 |
| 有跳变但 UART 乱码 | 检查 115200/8N1/不反相/门限；测 8.68 us 单位时间，核对系统时钟与采样率 |
| STM32 PA9 有波形，FPGA J3.1 没有 | 检查连接线、针号；必要时两个通道同时看两端 |
| CH0 正确，CH1 无回传 | 先确认下载了当前 FPGA 设计、XDC 与实际引脚、输入十字节 XOR；逻辑分析仪看不到内部 FSM 状态 |
| CH1 正确，PC 无数据 | 查外置串口 RXD/共地/COM；不要误选板载 USB/UART3 |
| I2C 地址 NACK | 查 MPU6050 3.3V、AD0 地址、PB10/PB11、SCL/SDA 是否接反 |
| I2C 最后一个读字节 NACK | 正常主机结束，不能当作从机故障 |
| I2C 总线持续为低 | 查线路、供电、模块及负载；分析仪不能凭数字波形确定具体模拟故障原因 |
| 接上探头后才异常 | 缩短探头/地线、减少重复探头；规格标注每路 15 pF 输入电容，探测也会增加负载 |

## 七、当前不必测的内容与证据保存

当前重点是 UART 115200 与 I2C 100 kHz，不必先探测 50 MHz 晶振，也不要把普通长线探头夹到 STM32 晶体引脚。芯片内部的 rx_valid、frame_valid、FSM、队列计数不会自动出现在外部分析仪上；它们继续由 Testbench 验证，未来若需要板上观察，可另行设计 ILA 或调试端口。

逻辑分析仪显示的是门限判定后的 0/1，不能据此证明电压正好 3.3V、上升沿质量或过冲。电压用万用表，边沿/振铃等模拟品质用示波器；不要用门限调节掩盖实际电平错误。

每次保留工程/波形和截图，并记录 DL16 型号、固件目标、FPGA ACK_ONLY 参数、通道接法、采样率、门限、触发方式、捕获时长及是否启用 RLE/毛刺过滤。截图至少分别显示一个字节、一个包和多个包的间隔。

按手册 PDF 第 40、41 页（印刷页码 37、38），使用 **文件 → 保存/另存为** 保留 `.atkdl` 工程，**文件 → 导出/导出原始数据** 用于另存波形。保存后应重新打开核对所需设置和波形是否齐全。必须区分：分析仪原始 BIN 是采样点数据，不是已经 UART 解码的十字节包，**不能直接交给 `host/capture.py --input-bin`**。需要先取得或转换 UART 解码出的字节流，再检查本项目的 XOR 和序号；手册未明确保证可直接导出为该字节格式，不假设已有自动转换工具。

原始参考路径与针号依据见 [STM32 板型核查](stm32_board_review.md)、[FPGA 约束说明](fpga_constraints.md) 和 [接线指南](wiring_guide.md)。本轮未修改固件、RTL、约束或工具设置，也未声称任何实际采集通过。
