# 第三阶段：原始数据通信闭环设计

本阶段已获用户授权，继续暂缓上板。目标是完成可仿真的 FPGA 闭环、PC 原始日志工具和基于用户提供标准库的 STM32 固件，不声称已经读取真实传感器或完成电气验证。前两阶段协议、RX、TX 和解析器保持不变。

## FPGA 数据流与接口

```text
pl_rx -> uart_rx -> packet_parser -> return_controller -> uart_tx -> pl_tx
                         |                |
                  最近合法三轴       当前包 + 等待队列
```

- `power_on_reset`：参数 HOLD_CLKS，配置初值使 rst_o 启动为高；连续时钟计满后同步释放。可选 restart_i 用于独立测试/未来内部复位，板级顶层固定为低，不猜测物理复位脚。
- `return_controller`：输入已验证的序号/三轴和 frame_valid_i；输出字节 valid/data，连接 TX ready/done。每次入队锁存完整 56 位样本，当前发送内容不受新样本覆盖。
- `monitor_core`：具有同步 rst 的可测试核心，串接前两阶段模块；导出最近样本和接收、校验、超时、序号、丢弃/完成计数。
- `top`：仅 clk、pl_rx、pl_tx 三个板级端口，实例化上电复位和核心。本轮不应用候选 XDC、不修改用户已有 Vivado 工程或缓存。

默认输出为现有十字节包，重新由已解析样本组包，不作无条件字节回显。可用编译参数 ACK_ONLY=1 选择每个被接纳的合法包只回传单字节 06；两种模式互斥，不在整包前额外插入 ACK，不改变输入协议。

## 回传控制、队列与周期

默认等待队列深度 4，另有一份当前发送快照。状态为 IDLE、SEND、ARM_DONE、WAIT_DONE。SEND 每次 valid/ready 握手交付一个字节，帧模式共十字节，ACK 模式一字节。最后字节被接受后先经过 ARM_DONE，忽略可能属于前一个字节的完成脉冲，然后等待最后字节的真实 done，才记录整包回传完成。

队列采用 56 位数组、读写指针和填充计数。满队列与出队同拍时允许新包入队；否则满时丢弃最新包，保留已有数据，产生 overflow_o 一拍并增加 dropped_count_o。所有诊断计数器为 32 位，按模 2^32 累计。复位清空当前包、队列和计数，正在发送的字节由 uart_tx 同步复位终止。

一个默认字节为 4340 拍；十字节回传约 868 us，另有少量控制周期。250 包/s 的目标间隔为 4 ms，留有处理余量。不能因此宣称任意速率或无限时长零丢包；上游没有反压，超载必须通过丢弃计数和 PC 序号检查暴露。

## STM32 端

使用用户提供的 `stm32/Libraries` 中 CMSIS 与 STM32F10x 标准外设库，保持库文件原样。2026-10-28 补充核心板原理图已确认 Y1 标称 8 MHz，保留外部 8 MHz、系统 72 MHz 编译配置；运行频率仍未实测。

新增应用使用 SysTick 毫秒时基，USART1/PA9 115200 二进制发送。传感器现按扩展板通讯接口 2 使用 I2C2/PB10/PB11、100 kHz，为 OLED 保留 PB6/PB7；引脚集中在 board_pinmap.h。提供固定已知样本模式与传感器模式。传感器模式检查 WHO_AM_I、配置既有寄存器，再轮询 DATA_RDY、连续读取六个原始字节，不用 delay_ms(4) 伪装传感器同步。

硬件 I2C 接收按 ST AN2824 区分单字节、双字节和多字节末尾 ACK/STOP；所有等待均有超时和错误出口。I2C 故障后停止当前事务并重新初始化外设，持续物理故障仍会报告失败而非保证自行恢复。UART 不混入 printf 文本。序号在成功取得一组样本后递增，即使随后发送失败也保留序号缺口。

## PC 与证据

PC 工具支持整包或 ACK 模式，保存原始二进制、逐样本 CSV 与 JSON 统计；支持离线读取仿真捕获，在线串口依赖 pyserial。按序号诊断跳号/重复，但不能把模 256 序号解释为无限精度丢包计数。原始值不直接宣称为去重力振动量或故障类别。

## 验证

每个新增 RTL 都配自检：上电复位及重新触发、回传快照/握手/反压/满队列/同时出入队/复位、核心异常恢复、top 两种回传模式及 250 包/s 负载。端到端从串行输入激励到独立串行输出解码，并写出可被 PC 工具读取的原始捕获。

软件验证覆盖协议编码/解码、分片/垃圾/损坏/截断恢复、日志与统计、STM32 可移植应用及传感器驱动的模拟依赖。尽可能使用真实标准库编译、链接 Keil 工程。所有模拟依赖测试和编译结果均与真实传感器/串口板测分开记录。
