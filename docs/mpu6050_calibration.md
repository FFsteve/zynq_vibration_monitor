## 已知问题与校准范围

此前两段各约12组的静止记录，Z均值约为 +21952.67 和 -11375.83 计数。近似正反放置、配置不变条件下，中点为 +5288.42 计数，半差为 16664.25 计数/g。这只支持较大加性偏置的假设，尚不足以写入最终补偿。原记录还存在姿态、实际配置与温度条件未充分验证的问题，见 `../report/sensor_zdown_validation_20261030.md`。

本次采用每轴两点、三轴共六面的零偏与比例校准。它不校正轴间不正交、交叉轴耦合、温漂或动态频响，也不能恢复传感器已经饱和的原始数据。不要把一个静止姿态的三轴均值全部减掉作为通用校准；重力分量需要保留。

## 采集前准备

使用已有 SensorSource 固件。优先采集逻辑分析仪 D0 上的 STM32 原始 UART；也可使用已经确认逐包一致的 FPGA raw 回传。禁止用 filtered/debug 版回传计算静态零偏：这些数据已经过 FPGA 去直流和 FIR，乘4也无法恢复静态分量。

先做一份初始化记录：沿用现有 I2C 接线，20 MS/s、立即采集约2秒，开始采样后复位一次 STM32。检查身份和关键配置的实际读回，而不仅是写操作：

| 寄存器 | 当前源码要求的读回值 |
| --- | --- |
| WHO_AM_I，0x75 | 0x68 |
| PWR_MGMT_1，0x6B | 0x01，初始化等待结束后检查 |
| CONFIG，0x1A | 0x02 |
| SMPLRT_DIV，0x19 | 0x03 |
| ACCEL_CONFIG，0x1C | 0x00，量程及自检位均需核对 |
| INT_ENABLE，0x38 | 0x01 |

当前 `stm32/bsp/mpu6050.c` 已实现配置回读，但仍应保存一次实物证据，确认实际烧录版本与配置。上述配置的名义目标是 ±2g、16384计数/g、250样本/s，实际通信和时序仍以记录为准。

建议通电静置3～5分钟后开始定量采集；这是本次操作建议，不是器件保证的稳定时间。保持供电、安装方式和环境一致。记录设备/固件版本、日期、预热时间和可获得的温度信息；当前十字节包不含芯片温度，不要凭空填温度值。

## 六种姿态与两轮记录

以传感器本身的轴标识为准，轴正方向竖直向上时，该轴静态测量的目标为 +1g。不能未经核实就把元件面朝上等同于 +Z。翻转后的零偏会影响原始读数，所以表中是校正后的目标，不要求原始数值已经满足。

| 姿态编号 | 放置要求 | 校正后目标X/Y/Z，单位g |
| --- | --- | --- |
| xp | X正方向向上 | +1 / 0 / 0 |
| xn | X正方向向下 | -1 / 0 / 0 |
| yp | Y正方向向上 | 0 / +1 / 0 |
| yn | Y正方向向下 | 0 / -1 / 0 |
| zp | Z正方向向上 | 0 / 0 / +1 |
| zn | Z正方向向下 | 0 / 0 / -1 |

用稳定支撑固定姿态，尽量校准水平/垂直，不要手持采样或让线缆拉动模块。每次翻转后放手，等待3～5秒，再记录20秒稳定数据，名义约5000包。若夹杂移动，应另存并重新采集稳定段，不任意删除不符合预期的静止值。

第一轮六面记为 `xp_r1`、`xn_r1`、`yp_r1`、`yn_r1`、`zp_r1`、`zn_r1`，用于估计参数。重新摆放后再采第二轮六面，记为对应的 `_r2`，用于独立验证，不用同一组拟合数据证明校准有效。记录总共12份。第二轮后可增加一次断电、重新预热后的第三轮，验证参数能否复用。

## DL16 的具体采集与保存

初始化捕获与六面长记录分开。六面记录只需要现有 D0 UART，关闭不需要的通道和解码器，减少存储量。

- UART：115200、8数据位、无校验、1停止位、lsb-first、不反相、hex。
- 长记录优先使用 Stream，记录20秒；采样率可用5 MS/s，约43个采样点/位。若软件没有该档，选择可用的10或20 MS/s并记录设置。
- 不要直接沿用20 MS/s、所有通道的长时 Buffer 配置。若无法进行20秒连续记录，同一姿态下可分段采集，例如每段2秒、共10段；保存全部段和实际有效样本数，段与段间的序号不能按连续通信统计。
- 以软件允许的时长、深度及实际记录区间为准，避免继续沿用此前50毫秒短记录作为正式标定数据。Stream也须核对无采集/解码异常，循环单次采集不能当作无缝连续记录。

每份记录至少保存原始 `.atkdl` 和对应 D0 的 UART 协议解码 CSV，例如 `xp_r1.atkdl`、`xp_r1_uart.csv`。保留起止时间、十六进制字节和错误项；只发截图不能用于可靠统计。波形导出的原始 BIN 不是已经解码的 UART 字节，不能直接传给 `host/capture.py --input-bin`。

若已有可正常接收 raw 数据的 PC 串口，也可在项目根目录执行：

```powershell
python -X utf8 host/capture.py --port COM7 --seconds 20 --output build/calibration/xp_r1
```

`COM7` 改成实际端口；每次输出目录必须不同。该命令只接收，输出 `capture.bin`、`samples.csv`、`stats.json`。现有工具不会判断输入是raw还是filtered，因此必须人工确认版本。仅有逻辑分析仪 USB 不等于有该串口，不要求为本次采集额外购买设备。

## 解码与统计

十字节仍为 `A5 5A SEQ XH XL YH YL ZH ZL CHK`。先验证 XOR，再将三轴按大端有符号16位还原。序号255到0为正常回绕；检查重复、序号缺口、停止位错误和实际包周期。采集首尾可能截断，从完整合法包统计，并保留边界情况说明。

每份稳定记录统计：有效包数、三轴均值、样本标准差、最小/最大值，以及记录前半段和后半段的均值差。检查原始读数是否饱和或明显漂移。20秒约5000包只是名义预期，不用强制凑齐数量。PC接收分块时间不能当作精确4毫秒采样时刻。

## 参数计算与校正

以X轴为例，仅取第一轮 `xp_r1` 中X的均值为 `mu_xp`，`xn_r1` 中X的均值为 `mu_xn`：

```text
bx = (mu_xp + mu_xn) / 2                 零偏，单位计数
Sx = (mu_xp - mu_xn) / 2                 灵敏度，单位计数/g
ax_g = (raw_x - bx) / Sx                 校正后加速度，单位g
kx = 16384 / Sx                         保持16384计数/g的比例系数
corrected_x = round((raw_x - bx) * kx)   校正后的整数计数
```

Y、Z分别使用自己的正反姿态计算，不能把Z参数套到其他轴。若S非正、变化异常或原始数据饱和，应检查姿态标记、解码和传感器状态，停止使用这组参数。

此前Z的数字仅作算例：`bz≈5288.42`、`Sz≈16664.25`、`kz≈0.98318`；它们不是已经验收的标定系数。六面两点方法参考 [Analog Devices AN-1057 的校准说明](https://www.analog.com/en/resources/app-notes/2020/07/22/16/49/an-1057.html)，用于估计偏置和比例，不代表该应用笔记给出了本项目的精度指标。

## 独立验证与后续固化

用第一轮得到的一套固定参数处理第二轮全部数据，计算每轴均值、标准差及每样本合成幅值 `sqrt(ax_g^2 + ay_g^2 + az_g^2)`。若姿态摆放准确，主轴应接近正负1g，另外两轴接近0g，合成幅值接近1g；不是三轴同时为0。

可先采用下列项目初步目标，它们不是MPU6050出厂保证，也不能替代比赛规定：

| 项目 | 建议初步检查目标 |
| --- | --- |
| 第二轮各主轴均值与目标的差 | 不大于0.05g |
| 第二轮非主轴均值绝对值 | 不大于0.05g；需先排除摆放倾斜 |
| 第二轮各姿态的合成幅值均值 | 0.97～1.03g |
| 两轮分别估计的同轴零偏差 | 尽量不大于0.01g，按标称约164计数比较 |
| 两轮分别估计的同轴灵敏度差 | 尽量不大于1% |

还应检查均值随时间的变化和波动，不能只看整段平均值。若结果超出目标，先检查摆放精度、温漂、机械应力、配置和供电状态，再决定是否需要更复杂的误差模型或更换模块；不要不断调参数去拟合第二轮。

验证通过后，再形成后续版本，将已确认参数应用到 STM32 加速度读取之后、UART打包之前。中间计算使用足够宽的类型并明确舍入，最终有符号16位输出应检查并处理溢出。保留原始记录和无校准固件，更新发送数据的语义说明并重新确认方案；既有十字节布局和XOR算法可以保持，但“字段为原始值还是校准值”必须明确。

FPGA去直流仍负责移除重力和剩余慢变分量，比例校正则影响振动幅值与RMS的实际单位。校准后重测原始回传、滤波输出和报警路径；现有2000/1500只是演示阈值，需要结合校正后的量值和实际场景重新评估。
