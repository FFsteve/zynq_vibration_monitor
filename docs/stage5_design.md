# 第五阶段：窗口特征、整数RMS与报警设计

日期：2026-10-31。状态：**用户已批准具体方案，四个RTL和自检已实现；实际验收状态见[实现报告](../report/stage5_validation.md)。**

用户要求继续原定第五阶段；项目上下文将其范围限定为窗口均方值、峰值和阈值报警。本方案补充整数RMS输出，便于后续显示。用户已确认128样本、2000/1500演示阈值及两窗确认，授权编写四个RTL并自动运行ModelSim/XSim。

## 本阶段范围

第四阶段已经输出同拍有效的signed18三轴、SEQ、历史完整、饱和/过载/重启状态。第五阶段只从这些内部接口接入，不再次采集传感器，不用原始带重力计数直接计算振动RMS。

```text
原有UART、解析及原始回传
    -> 第四阶段去直流/FIR
    -> 质量门控、128样本非重叠窗口
    -> 三轴均方值、绝对峰值、整数RMS
    -> 每轴RMS滞回及连续窗口确认
    -> 对齐的特征与报警内部接口
```

当前十字节UART输入和原始回传保持原样，板级top、XDC、STM32和烧录设置不变。新特征和报警先作为内部接口供自检及后续上位机阶段使用；本阶段不为LED猜引脚，也不自行添加结果包或占用原始字段。

报警是参数化演示功能，不表示工业故障分类。MPU6050的实际配置/校准、采样均匀性和真实阈值标定继续留待最终联调。

## 数学定义与默认参数

| 项目 | 默认值或规则 |
|---|---|
| 名义采样率 | 250Hz，频率和时间换算依赖实际采样均匀 |
| 窗口 | 128个有效样本，非重叠；名义输出间隔512ms |
| 三轴处理 | 各自平方、累加、峰值和报警，不混为矢量模长 |
| 均方值MS | `floor(sum(x²)/128)`，单位为计数平方 |
| RMS | `floor(sqrt(MS))`，单位为原始计数；误差小于1计数 |
| 峰值 | `max(abs(x))`；不是峰峰值 |
| 报警置位 | 每轴MS达到2000²，连续2个完整窗口 |
| 报警解除 | 每轴MS不高于1500²，连续2个完整窗口 |
| 合成报警 | 三个轴报警位逻辑或；不是矢量RMS阈值 |

阈值2000/1500仅为仿真和竞赛演示起点，使用原始计数，不转换为未经校准的g值。参数在综合/仿真时配置，本阶段不实现PC实时改阈值。

窗口最后一个样本必须同时计入能量和峰值。除法采用二次幂右移，不能先对每个平方舍入后再累加。用整数阈值的平方比较MS，可避免报警依赖开方舍入；对整数门槛，与比较真实RMS是否达到该门槛等价。

`WINDOW_LOG2`允许0～10，窗口长度为2的该次幂；默认7。允许N=1用于边界测试。阈值满足 `0<=OFF<ON<=131072`；置位/解除连续窗口数分别允许1～255。非法参数必须明确拒绝，不能静默回退。

### 滞回和连续确认

每轴独立保存当前报警位、置位连续计数和解除连续计数：

- 未报警：MS≥ON²时增加置位计数，达到指定窗口数才置位；不满足时置位计数清零。
- 已报警：MS≤OFF²时增加解除计数，达到指定窗口数才解除；不满足时解除计数清零。
- 在OFF²与ON²之间保持现有报警状态，但中断连续确认，不能把隔开的两次超限拼成连续两次。
- SEQ回绕正常；复位、无效历史、饱和、过载、断流或重新建窗时，清确认计数并将 `alarm_valid_o=0`。报警位清零不代表测量正常；不得把数据失效导致的清零伪装成一次正常解除事件。

首次完整窗口完成后 `alarm_valid_o=1`；若默认需要两个高窗口，该时刻尚未报警是确认策略的结果。后续没有新特征时，报警与确认计数保持，不按PL时钟累计。

## 数据格式与界限

| 数据 | 格式及界限 |
|---|---|
| 滤波输入 | signed18，-131072～131071 |
| 输入平方 | 完整18×18乘法36位；实际非负最大2³⁴ |
| 默认窗口累加器 | unsigned43，最大128×2³⁴=2⁴¹，不溢出 |
| 通用累加器宽度 | `36+WINDOW_LOG2`，保留完整乘积后再扩展累加 |
| 均方值输出 | unsigned35，0～2³⁴ |
| RMS输出 | unsigned18，0～131072 |
| 绝对峰值输出 | unsigned18，0～131072；先扩展到19位再取绝对值 |
| 平方根内部输入 | unsigned36，支持0～2³⁶-1 |
| 通用平方根输出 | unsigned18，最大262143；余数unsigned19 |

均方值、RMS、峰值均为无符号量，不能复用signed18信号解释131072，否则最负输入的绝对值会再次被解释成负数。阈值先扩展到至少36位再平方，防止32位integer乘法溢出。解除条件严格按MS≤OFF²执行；因MS先向下取整，与未取整均方在OFF²边界最多相差不足1计数平方。

## isqrt_u36接口和时序

已实现 `rtl/isqrt_u36.v`：输入 `clk/rst`、`valid_i`、unsigned36 `radicand_i`；输出 `ready_o`、`valid_o`、unsigned18 `root_o`、unsigned19 `remainder_o`。

仅 `valid_i && ready_o` 的沿锁存输入；忙时一拍请求不接纳，若保持请求须保持数据直到ready。复位优先，取消在途结果。

状态为IDLE和RUN，保存36位被开方移位寄存器、18位部分根、19位余数、5位迭代索引。每拍取下一对最高位，使用足够扩展的21位暂存量比较并减去 `(root<<2)|1`，形成下一根位；共18次迭代，无除法或浮点IP。

接纳沿t=0，t=1～18逐次迭代，t=18提交最终根与余数并产生有效脉冲；t=19最早接纳下一请求。验收使用独立 `math.isqrt`，必须满足 `root²<=n<(root+1)²` 和 `remainder=n-root²`。

## window_features接口、寄存器和状态机

已实现 `rtl/window_features.v`：输入 `clk/rst`、`clear_i`、一拍 `sample_valid_i`、SEQ和signed18三轴；输出 `ready_o`、一拍 `feature_valid_o`、三轴MS/RMS/峰值、窗口首末SEQ、32位window_id、overrun与序号不连续事件，以及累计接纳/丢弃/废弃窗口计数。

这是事件接口，沿用第四阶段风格：仅ready时接纳样本；上游不会等待。忙时收到事件将记一次overrun，并取消当前部分或在途窗口，不把丢样前后拼接成连续窗口。清理后下一个合法样本开始新窗。`clear_i`优先于样本和计算完成；clear期间样本有意忽略，不计成过载。

主要寄存器为：三轴输入快照和SEQ、三份36位平方、三份默认43位能量和、三份18位峰值、样本计数、首SEQ、上一个SEQ、窗口结果快照及计数器。使用三套平方乘法器、三套并行整数开方器；完整通信/滤波/统计核心实际OOC资源为3205LUT、5894FF、6DSP、0BRAM，详见实现报告。

| 状态 | 行为 |
|---|---|
| IDLE | ready=1，锁存一个三轴样本及SEQ |
| MUL | 并行计算三轴完整36位平方 |
| ACC | 更新三轴能量和峰值；非末样本返回IDLE，末样本锁存MS与峰值并进入ROOT_START |
| ROOT_START | 向三个平方根模块同时握手提交MS（前补0成为36位） |
| ROOT_WAIT | 等待三个根同拍完成，提交完整窗口及feature_valid，返回IDLE |

输入接纳为t=0：t=1平方，t=2累加。非末样本最早t=3可接纳下一样本；末样本t=3提交平方根请求，t=4～21开方，t=22提交完整窗口，最早t=23接纳下一样本。第四阶段最短输出间隔194拍，因此正常连接下有充分余量；不能凭该计算就省略过载自检。

末样本提交后清空下一窗口的和/峰值/样本计数，不重复使用上窗最后一个样本。window_id仅在窗口发布时递增，首窗ID=0；质量清理不重置累计ID，只有全局rst重置。

### 连续性和取消规则

- 仅有效接纳的样本推进窗口；空闲拍不制造样本。
- 模256的SEQ连续，包括FF→00；跳号或重复时废弃尚未发布的旧窗，以当前样本作为新窗第一项，并输出不连续事件。
- 明确clear或忙时overrun取消在途平方、累加或开方，后续不得泄漏旧feature_valid。
- `aborted_windows`计入被废弃的部分或已凑满但尚未发布的在途窗口；clear保持多拍只计一次，不空窗重复计数。统计诊断只由全局rst清零。
- 模块不根据SEQ重造丢掉的样本，也不通过补0凑满窗口。

## threshold_alarm接口与事件

已实现 `rtl/threshold_alarm.v`：输入 `clk/rst/clear_i`、一拍 `feature_valid_i`、unsigned35三轴MS；输出 `alarm_axes_o[2:0]`（bit0=X、bit1=Y、bit2=Z）、`alarm_any_o`、`alarm_valid_o`，以及三位上升/下降事件脉冲。

没有需要等待的计算状态，按每个特征事件分别更新三轴计数和状态。`clear_i`或rst优先，同拍特征忽略，状态有效性清零；这种质量清理不产生正常解除事件。参数化连续窗口数1时应在当前特征直接切换，不能多等一个窗口。

## feature_monitor_core连接及对齐

已实现 `rtl/feature_monitor_core.v`，复用第四阶段 `filter_monitor_core`。原始UART回传、原始诊断和滤波支路保持现有实现，新增窗口与报警内部接口。

窗口clear来自滤波历史不完整、饱和、过载或重启。报警clear还包含窗口overrun及不连续事件。只有质量有效的完整FIR样本进入窗口，首次采样的前62个补零瞬态不参与统计。

`window_features`在末样本后的t=22输出特征，`threshold_alarm`在t=23处理该特征；适配层同时把该特征数据延迟一拍，发布对齐的特征、窗口ID和更新后的报警，避免新特征配旧报警。质量clear会取消该延迟拍的待发布结果。

适配层的特征有效脉冲与报警状态有效标志分别表达“新窗口到达”和“当前存在可信状态”；数据失效时外部必须看有效标志，不能只看alarm=0。连续静默由第四阶段的12ms断流门控使状态失效，本阶段不再创建第二个冲突的采样时钟。

## 时间含义

128样本窗口的名义更新间隔512ms，但首项到末项相隔127个采样间隔，即508ms。正常启动时，第四阶段第63个输出（原始样本索引62）开始可统计，第一窗口末项为索引189，距首个原始样本约756ms，再加约4.36us数字流水延迟（解析帧进入滤波1拍、滤波193拍、下游接纳1拍、窗口末样本处理22拍、报警对齐1拍，共218拍）。

默认连续两个高窗口才报警，因此在从启动即持续满足门槛的理想条件下，第二窗口末项索引317，约1.268s；这不是任意真实故障的保证响应时间。上述时间以均匀250Hz为前提，不额外重复加上FIR的124ms信号群延迟。
